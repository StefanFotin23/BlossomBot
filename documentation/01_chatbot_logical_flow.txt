=========================================================
TECHNICAL DOCUMENTATION: CHATBOT LOGICAL FLOW
=========================================================

1. INTRODUCTION
The logical flow of BlossomBot is built around an asynchronous State Machine, implemented in Python using the Slack Bolt framework and an LLM (Gemini 3.1 Flash-Lite) acting as a decision router. This architecture enables the bot to handle non-linear conversations, retain user context across multiple turns, and function as a fully-fledged conversational e-commerce assistant.

2. THE STATE MACHINE (CONVERSATIONAL STATES)
Each user's state is tracked persistently (via Redis) using their unique Slack `user_id`. The application handles the following states:

- GREETING: The initial state. The bot introduces itself and invites the user to browse. It also acts as a "soft reset" point.
- CATALOG_DISCOVERY: Triggered by broad questions (e.g., "What products do you have?"). It bypasses strict filtering to offer a diverse, representative sample of the catalog.
- SEARCH_PRODUCTS: The core RAG state. It extracts filters from the user's input, searches the vector database, and returns the most relevant products while applying dynamic relaxation if necessary.
- PRODUCT_DETAILS: When a user asks for more information about a previously displayed product. The bot expands metadata into a readable list and shows full descriptions.
- PURCHASE_INTENT: The user selects a product. The LLM extracts index and quantity.
- AWAITING_CONFIRMATION: The bot asks for confirmation. Detects "Yes" (handling "afirmativ", "da", "vreau") or "No" (handling "negativ", "nu").
- VIEW_CART: Displays internal cart array and total value.
- FINISH_ORDER: Triggers RabbitMQ dispatch and executes a "Hard Reset".
- RESTART: Clears cart and memory, reverting to GREETING.

3. INTENT ROUTING & SMART UX FALLBACKS
- HYBRID TWO-TIER INTENT GATEWAY: Routes queries locally using a sub-millisecond local GRU classifier (Tier 1) with contextual Bayesian prior adjustments based on previous conversational state. Delegates to Gemini HTTP API (Tier 2) only for complex or multi-intent requests.
- SEMANTIC KEYWORD GUARDRAILS: Implements heuristic keyword checks on critical GRU-predicted intents (FINISH_ORDER, REMOVE_FROM_CART, VIEW_CART, RESTART, GREETING) to prevent false positives from out-of-vocabulary (OOV) overfitting and politeness bias.
- COMMAND FAST-PATH: Deterministic interception before LLM for basic commands.
- REFINED SELECTION REGEX: Manual index matching ignores numbers followed by quantity keywords (e.g., "5 bucăți"), preventing misrouting quantities as item indices.
- SMART SELECTION PIVOT: If a user says "da" but no index is found (e.g., results were lost), the bot asks for clarification ("What product do you want to add?") instead of random search.
- UX-FIRST SEARCH FALLBACK: If a search returns zero results, the bot automatically shows "Popular Products".
- MULTI-INTENT DECOMPOSITION: Splits complex messages into sequential tasks via background QoS queue.


4. SHOPPING CART AND CONTEXT RESET ("HARD RESET")
- Persistent Search Memory: Preserves `last_results` even after adding an item, allowing multi-item selection.
- visual delimiter (━━━━━━━━) indicates order completion.
- Immediate Persistence: Memory is overwritten with an empty dictionary upon "Hard Reset".

5. CONVERSATIONAL PACING & CONTINUATIONS
- THE CONTINUE INTENT: Users can trigger the next task using "ok" or "continuă".
- EMBEDDED CONTEXT RESUMPTION: Uses bridge messages like "Acum să ne ocupăm de: [task]...".
- PACED DELIVERY: Strategic 1.0 - 1.5s delay between tasks to prevent message flooding.
