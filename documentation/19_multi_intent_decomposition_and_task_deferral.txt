=========================================================
TECHNICAL DOCUMENTATION: MULTI-INTENT DECOMPOSITION
=========================================================

1. INTRODUCTION
BlossomBot handles complex sentences (e.g., "Add the first one and then show me some chocolates") by decomposing them into atomic tasks using a specialized LLM task array.

2. DECOMPOSITION ARCHITECTURE
- ATOMIC TASK ARRAY: Messages are split into objects with `text` and `intent`.
- DEFERRED TASKS: Secondary tasks are stored in a `deferred_tasks` list in Redis.
- QUANTITY CONTEXT PROTECTION: The decomposition prompt ensures that numbers appearing near selections (e.g., "1, 5 bucăți") are kept within a single `PURCHASE_INTENT` task rather than being split into separate searches.

3. SEQUENTIAL EXECUTION & PACING
- Blocking Actions: The loop pauses for manual confirmation (e.g., "Vrei să adăugăm...?") before resuming.
- EMPATHETIC BRIDGE PHRASES: Uses Romanian transitions like "Acum să ne ocupăm de..." or "Trecem la..." to maintain a human-like pacing during multi-task delivery.
- Fluid Execution: Non-blocking tasks are delivered in a single turn with a 1.5s delay for readability.

4. SHADOW TASK BUFFERING (LATENCY ELIMINATION)
- BACKGROUND PRECOMPUTATION: While a user confirms an item, the next task is processed in the background and cached in `buffer:{user_id}`.
- ZERO-LATENCY RESUMPTION: The next result is delivered instantly from the buffer, bypassing AI processing time.
- ISOLATION: The shadow buffer uses a separate key to prevent corruption of the live session.

5. BENEFITS
- Zero Data Loss: No part of a complex request is ignored.
- Context Retention: Search tasks receive cleaner, split queries for higher RAG accuracy.
- Premium UX: The bot feels attentive and capable of handling sophisticated human requests.
