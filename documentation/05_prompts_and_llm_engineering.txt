=========================================================
TECHNICAL DOCUMENTATION: PROMPTS & LLM ENGINEERING
=========================================================

1. INTENT ROUTING PHILOSOPHY
BlossomBot uses Gemini (Flash-Lite) as a "Central Brain" or Intent Router. Instead of relying on open-ended generation, it enforces Strict Classification guided by business logic.
- Defined States: The system operates on a closed set of intents (e.g., `GREETING`, `SEARCH_PRODUCTS`, `PRODUCT_DETAILS`, `FINISH_ORDER`).
- System Prompts: The prompt provides explicit rules (e.g., "Rule 1: Any request for a specific product is SEARCH_PRODUCTS").
- Zero Temperature: To ensure lightning-fast responses and 100% deterministic outputs (zero hallucinations), the Gemini configuration enforces `temperature: 0.0` and limits the output to a few tokens (just the state name).

2. DYNAMIC FILTER EXTRACTION
Converting natural language ("I want cheap purple tulips") into structured database queries (JSON).
- Dynamic Schema: At startup, the application reads the dataset and generates `schema.json` (containing exact valid categories, colors, etc.). This schema is injected into the LLM prompt, forcing Gemini to output database-compliant strings.
- Output Structure: The LLM returns a structured JSON containing:
  1. `filters`: The cumulative filters based on the current message and chat history.
  2. `semantic_query`: A text summary of desired product features.
  3. `mentioned_now`: A list of filter keys the user explicitly stated *in the current turn*.
  4. `insisted`: A list of filter keys the user is frustrated about or repeats (e.g., "too expensive" -> `price_max`).

3. SMART CONFIRMATION (YES/NO PARSER)
Traditional regex-based chatbots fail on conversational confirmations like "k", "yep", or "sure, I want 3".
- The `parse_confirmation` function utilizes a zero-temperature LLM prompt to classify the user's intent as `confirmed: true/false`.
- It simultaneously extracts a new `quantity` if the user adjusts their order during the confirmation step (e.g., "Yes, add 5 pieces").

4. HYBRID FORMATTING (TEMPLATES)
When returning product details, we avoid using the LLM to generate the final text. LLMs can hallucinate prices or details.
- Approach: Python scripts (`generate_hybrid_response`, `generate_detailed_product_info`) take the exact JSON metadata returned by Qdrant.
- They aggressively parse and clean the text (stripping raw HTML tags like "Body (HTML):") and format the data into clean, readable Markdown lists for Slack.
- This guarantees 100% data accuracy with zero latency for formatting.

5. DETERMINISTIC "SMALL TALK"
For general inquiries ("Who are you?", "Are you online?"), the system avoids expensive generation. It uses a zero-temperature LLM call simply to classify the question into predefined buckets (`IDENTITY`, `AVAILABILITY`, `HUMOR`). It then instantly returns a friendly, hardcoded string.
