=========================================================
TECHNICAL DOCUMENTATION: RAG & HYBRID SEARCH ENGINE
=========================================================

1. INTRODUCTION
BlossomBot employs a State-of-the-Art (SOTA) Hybrid Retrieval-Augmented Generation (RAG) architecture. Rather than relying solely on semantic search—which often fails when users apply strict numerical constraints (e.g., maximum price)—the system combines exact metadata filtering with vector similarity search and Cross-Encoder reranking.

2. OFFLINE NLP MODELS
To ensure high performance, privacy, and resilience against network restrictions, the application downloads and runs its NLP models entirely offline on the CPU:
- Embedding Model (`SentenceTransformers`): Converts product descriptions and user queries into 384-dimensional dense vectors.
- Cross-Encoder Reranker: Receives a pair of texts (User Query + Retrieved Document) and computes a highly accurate similarity score (0.0 to 1.0). This re-orders the initial broad vector search results to ensure the absolute best match is presented first.

3. VECTOR DATABASE (QDRANT)
Qdrant serves as the vector search engine. During initialization, Qdrant receives all product embeddings along with a JSON `payload` containing hard metadata (price, category, event_type, etc.). Similarity is calculated using Cosine Distance.

4. DYNAMIC FILTER RELAXATION & EXCLUSIONS
The search engine incorporates a synergistic "Positive + Negative" filtering system.
- Negative Filters (Exclusions): Users can explicitly exclude features (e.g., "no roses" or "anything but yellow"). These are extracted into a `negative_filters` object and applied as `must_not` conditions in Qdrant.
- HOLIDAY-SPECIFIC MAPPING: For Romanian traditional items like "Mărțișoare," the system applies a special mapping rule. The LLM is instructed to map these queries to `event_type`: `1 Martie`, ensuring hard-filtered relevance over loose semantic similarity.
- Dynamic Relaxation: When a user applies multiple strict constraints, the system executes a progressive relaxation algorithm:
   * Importance Scoring: Each constraint (positive or negative) carries a score managed in `app/bot.py`.
   * Exclusion Synergy: Negative constraints are integrated into the importance hierarchy. If a user insists on "no roses," that exclusion gains points and survives longer during relaxation than a casual positive mention.
   * Successive Search: The engine sorts all active constraints by score and executes successive Qdrant queries. 
   * PRIORITIZED FALLBACK ORDER: The system now strictly prioritizes `category` and `flowers_type` over secondary attributes. If a search is over-constrained, secondary filters like `price_max` and `colors` are dropped FIRST, ensuring the user always sees the correct type of product (e.g., a "Mărțișor") even if the requested color is unavailable.

5. DIVERSIFIED FALLBACK (SEMANTIC JITTER)
If relaxation drops almost all filters and falls back to a pure "Semantic Only" search, the system avoids presenting monotonous results:
- Semantic Jitter: The system retrieves a larger pool of results (e.g., top 10), preserves the absolute best semantic match at position #1, and randomly shuffles the subsequent results. This provides variety if the user repeats the same vague query.
- Category Diversification: The algorithm iterates through the reranked hits and attempts to fill the final "Top 3" list with products from different categories (e.g., one bouquet, one plant, one gift box), maximizing the chance of serendipitous discovery.

6. METADATA FEEDBACK
When filters are dropped during dynamic relaxation, the engine returns a `failed_filters` array. The bot uses this data to provide transparent, guided feedback to the user (e.g., "I adjusted the search. The closest options start at X RON.").
